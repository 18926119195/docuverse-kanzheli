### 怎样观测和纠偏

借用钱学森《工程控制论》的工程视角，把开发目标、输入、可观测状态、反馈和纠偏落实到协作与验收。每次变更都应能沿这条链回查。

| 项目 | 本仓库的检查点 |
| --- | --- |
| 输入 | PDF 页面布局、OCR 文本、peek 批次和修贴操作 |
| 输出 | bookKey、briefKey、目录入口及贴条记录 |
| 可观测验收 | 55 页夹具首尾共 40 页，批处理并发峰值 2，同族多贴通过而跨族直接追加被拒绝 |
| 偏差处理 | 遇到 OCR 缺页或越族贴条时，记录页号、layout 书门与 peekFamilyId，先用同一夹具检查调度与母族规则。 |

在仓库根目录运行以下命令。当前离线夹具覆盖BM25、同问复键、三态、OCR 页序、并发和贴条母族。真实模型、OCR 和生产部署的行为需要有相应环境才能验证。

```sh
npm ci --ignore-scripts
npm run build
npm run check:system
```

提交 PR 时附时间线编号、基线提交、实际入口、预期与实测。如果实测偏离预期，用同一输入记录最小复现并附相关台账或模型请求中的非敏感字段。行为修正通过同一检查后，将决定、代码和结果补回时间线。已发布版本出现回归时，先保留失败证据，再由维护者评估回退对应变更或修正向前。
